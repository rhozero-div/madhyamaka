# 中觀學 · 印度、中國、日本的中觀傳統

> 从恒河到长安，再到奈良——一条关于「空」的思想线索，走了约一千八百年。

**在线浏览：<https://rhozero-div.github.io/madhyamaka/>**

以大正藏三十部典籍为底本，上溯印度论师的造论与注疏，下及隋唐三论宗的判教与注疏，终至日本南都三论宗的承袭与变形。单文件静态站点，无外部依赖。

## 阅读注疏器

`reading.html` 是阅读目录（二级），由此进入三级页：`T42n1824.html`（《中观论疏》，T42 no. 1824）、`T08n0251.html`（《心经》，T08 no. 251）、`glossary.html`（术语表）。页面文件名取大正藏号，与 `text/<号>.json`、`annotations/<号>.json` 同名，看到编号就知道是哪种文本。阅读页带注释功能，**须走本地服务**才有存盘能力，不能双击打开——`file://` 下列表读不到正文 JSON，注也无处可写；线上（GitHub Pages）打开时没有写接口，自动转为只读，见上节。

最省事的开法：双击项目根目录的

- `開啟論疏.command` → 《中观论疏》
- `開啟心經.command` → 《心经》

已启动服务就直接开页，未启动就先起服务再开；关掉那个终端窗口即停服务。

或在终端里手动：

```bash
python3 serve.py
# 阅读目录 http://127.0.0.1:8765/reading.html
# 中观论疏 http://127.0.0.1:8765/T42n1824.html
# 心经     http://127.0.0.1:8765/T08n0251.html
# 术语表   http://127.0.0.1:8765/glossary.html
```

用法：划选正文即浮出「加注」，写完点「存」；存与取消只用鼠标点按钮，编辑器内不设键盘快捷键（输入法用 Esc／Enter 时会与之冲突，导致注文尽失）。点正文注号跳到该节末尾的注，点注末序号跳回正文；「白文」开关隐去全部注号与注释。

**顶栏「術語」**：直达术语表（`glossary.html`）。注文中带下划线的词点开即见该条释义，术语表里点任一条可改；释义留空的标「待撰」，暂不在注文里加链。顶栏原有的「＋串講」按钮已撤（注释已定稿，不再从页面上新建句末串讲），数据里那几条零长锚的串讲仍照常渲染。

数据分三层存放，互不牵连：

| 层 | 位置 | 说明 |
| --- | --- | --- |
| 正文 | `text/<大正藏号>.json` | 由 `tools/prep.py`（论疏）、`tools/prep_heart.py`（心经）自 CBETA XML 生成，段落锚点用官方 `xml:id` |
| 注释 | `annotations/<大正藏号>.json` | 每写一条即落盘，按文本分文件 |
| 渲染 | `assets/reader.css`、`assets/reader.js` | 页面只以 `<body data-text="…">` 指定文本，其余由 JSON 的 meta 决定 |

注释锚在「段 id + 起止偏移（`offset`／`end`）+ 所注原文」上，故正文重新切分或换底本时注不会错位。**角标画在所注文字的右端**：整句之注落在句末，句中之词注依次在前，读时先词后句；同一单元内按右端位置编号，右端相同者短注在前。旧注只存起点，用 `offset + 引文长度` 补出右端；句末串讲则 `offset` 与 `end` 同取该单元止处，`quote` 留空。

### 注文分三截

一条注可分「原义 / 观义 / 串讲」三栏，另附「所引」，页上各带小标签显示：

```json
{ "id": "…", "para": "pT08p0848c0601", "offset": 17, "end": 19, "quote": "五蘊",
  "parts": [ {"k": "原义", "t": "…"}, {"k": "观义", "t": "…"}, {"k": "串讲", "t": "…"} ],
  "src": [ {"w": "《中论》", "p": "观行品第十三",
            "q": "大聖說空法，為離諸見故；\n若復見有空，諸佛所不化。",
            "l": "T30.1564.0018c16–17"} ] }
```

三栏皆可空，填一栏即可存；`src` 用于日后汇总「本书所引经论」。旧注只有 `note` 一个字串，照原样显示、照原样保存，**不强制迁移**；改旧注时编辑器另现「旧注」一栏，可剪入上三栏，若已剪入则不另存一份。

### 所引的写法

一书一条，四个字段，皆可空：

| 字段 | 内容 | 例 |
|---|---|---|
| `w` | 书名 | `《中論》` |
| `p` | 品名（含品次） | `觀行品第十三` |
| `q` | 原文，换行照录 | `大聖說空法，為離諸見故；……` |
| `l` | 出处与校记 | `T30.1564.0018c16–17` |

- 经文原文与注文同为繁体，读者不必在两种字体间切换（见下〈用字〉）
- `l` 用 `T30.1564.0018c16` 这种「册·经号·页栏行」写法，可直接回查纸本；有异文时把校记接在后面
- 旧数据为纯字符串（如 `"《杂阿含经》"`）者仍照旧显示；在编辑器里打开会转成一条只有书名的条目
- 只写书名、不录原文亦可，此时该条只作书目引用，页上仅出一行书名

编辑器里点「＋ 书名／品名／原文」增一条，每条右上「×」删去，至少保留一条空行。

### 用字

**网页层一律繁体**（台湾正体）：正文、注文、术语释义、界面文案，无一处简体。输入不限——用简体输入法写，`serve.py` 存盘前会自动转繁，并把转好的那份回给页面即时重绘，所以存完当场看到的已是繁体。

- 转换在服务端做（`tools/to_trad.py`，OpenCC `s2t`），不依赖浏览器，也不必记得手动转
- 七字保留原形：**注、才、峰、面、群、核、朱**。OpenCC 会把它们误作註、纔、峯、麪、羣、覈、硃；佛典「注疏」從來用「注」，其餘六字亦以通行正體為準
- 「云」亦保留：OpenCC 会把「論云」误作「論雲」，而注文引書滿是「經云」「故云」
- 引号用古籍体：外「」、内『』。输入法默认给的是 “”‘’，存盘前一律换成角括号，与 CBETA 原文和全站文案一致；`src.q`（所引原文）只换引号、不转繁简，免得动了底本用字
- 另作三处归一：「衆」→「眾」（随大正藏底本）、「裏」→「裡」、「爲」→「為」、「註」→「注」
- `text/*.json` 的古籍原文**不经转换**，一仍底本用字；`sources/*.md` 亦然。已存的旧文可跑 `python3 tools/to_trad.py --check` 体检、`--apply` 批量转

### 术语表

`glossary/terms.json` 收名相（`k` 词、`t` 释义、`aka` 异名、`auto` 是否自动加链、`refs` 所据），页面 `glossary.html` 可直接编辑，走 `POST /api/term` 落盘。注文里凡有释义的术语，首次出现自动加链（同一注只链一次），点开见释义卡；**释义为空者标「待撰」，暂不加链**，免正文满目虚链。临时想在注里点某个未收的词，写成 `{{词}}` 即可，卡片会显示「待撰」并给编辑入口。

释义用空行分段，卡片按段渲染，过长则卡内滚动。术语表与注文的详略分工不同：注文求简，只给「可破的对象」；**术语表求备，小乘、部派诸解与中观并列，不为突出中观而略写**——读者点开一词，先看见它在佛教史上的几层意思，再看中观如何取舍。

一条术语也可带「所引」（`src`，字段与注文所引全同：`w` 书名、`p` 品名、`q` 引文、`l` 行号），卡片在所据之前以朱线引出原文，如「滅」条引《中观论疏》「生不自灭，由生故灭」一段。该栏现由 JSON 维护：编辑框里只读显示书名品名，注明「引文在 `glossary/terms.json` 中改」；`POST /api/term` 存盘时原样带过，不会因改释义而丢失。

接口：`GET /api/terms`、`POST /api/term`（`op` 为 `add`／`update`／`delete`），与 `GET /api/notes?t=<号>`、`POST /api/note` 并列，均只绑定 `127.0.0.1`。

GitHub Pages，`main` 分支根目录直接发布（Settings → Pages → Deploy from a branch → `main` / `(root)`）。根目录 `.nojekyll` 用于跳过 Jekyll 处理。

```bash
git add -A && git commit -m "更新内容" && git push
```

约一分钟后线上自动更新。
